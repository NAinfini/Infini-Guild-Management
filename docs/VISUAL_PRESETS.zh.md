# 视觉主题素材约定

[文档首页](../README.md) · [English version](./VISUAL_PRESETS.md)

门户通过 `apps/portal/visual/themes.ts` 中的一份类型化 manifest 和一套 UI 实现管理视觉主题。环境图绝不替代成员头像、图库作品、物品照片或公告/百科内容媒体。站点配置拥有显示名称和 Logo；可访问文字、控件、焦点与对比度仍由应用负责。

## 启用方式

在门户构建环境或 `.env.local` 中设置 `VITE_VISUAL_THEME=forged`。省略时选择 `forged`，未知值会明确失败。当前素材包版本为 8。

## 工作区场景

既有 `components/layout/route-metadata.ts` 注册表为每个路由分配 `workspaceScene`。嵌套页面继承父页面场景，不存在另一套路由或标签页图片注册表。

| 场景 | 路由 | 视觉身份 |
| --- | --- | --- |
| `guild` | 总览、活动、成员 | 宏大的临河公会都城，拥有宽阔宫殿与城市街区 |
| `falls` | 公告、百科、图库 | 巨型瀑布与建在稳固石台上的滨水公会建筑群 |
| `citadel` | 公会战、仓储、工具、个人资料、设置、管理后台 | 两岸分布巨墙和宫殿街区的堡垒港湾 |

每个场景在 `public/visual-themes/forged/workspace/` 下有四个不透明 WebP 文件：

- `<scene>-desktop.webp` 和 `<scene>-mobile.webp`：日间版本；
- `<scene>-desktop-dark.webp` 和 `<scene>-mobile-dark.webp`：与对应日间构图分别生成的夜间版本。

桌面场景为 1672×941，竖屏场景为 941×1672。这是内置图片生成器在请求最大输出后返回的原生文件，并非 2K 或 4K 素材。12 张图片都在不缩放的情况下导出为无损 WebP，导出时会将解码像素与原 PNG 比较。manifest 声明精确生产尺寸，并与发布文件核对。生成的日夜对具有相同原生尺寸。

这些场景是史诗感建筑全景，不使用近景巷道、院落或框景柱。宏伟感来自连贯的城市体量、宽阔殿堂和结构合理的防御工事，而非重复塔楼或山峰。内容通常遮住中央 70–80%，因此大型屋顶、城墙、瀑布和滨水地基要延伸到上下左右边缘。完整无遮挡图片仍须是一个连贯环境，不能包含人工边框或中央空矩形。天然材质、克制光线和随距离递减的细节可避免全画面同等锐化。竖屏图独立构图，不从桌面图裁切。

`AppShell` 将一个不可交互场景放在真实内容网格中，位于页头下方及侧栏旁边；紧凑导航还会排除底栏。`VisualThemeScene` 使用一个响应式 `<picture>`，在 768px 以下选择竖屏图，并根据当前主题选择正确日夜来源。同一场景组内切换路由会复用素材。

日间场景使用 18% surface-base veil，夜间场景使用 6%。所有可读内容组都使用不透明语义表面。不得用不透明整页画布或厚重全局遮罩隐藏场景。导航保持不透明且不使用单独场景。没有视差或循环背景动画。

## 公共、访问和状态场景

既有首页、登录、注册和四种状态场景在 `public/` 与 `public/light/` 下保留各自桌面/手机及明暗素材。桌面素材为 3840×2160，竖屏素材为 2160×3840；这些尺寸只描述公共素材。

登录和注册页在桌面保留安静的右侧表单区域，手机则把表单放在场景焦点上方。账号恢复和邀请码验证使用登录图组。HTML splash 在轻量语义背景上保留注入的站点配置 Logo、站名和状态，并在 React 挂载前解析持久颜色模式；它不会预加载或显示场景图，真实页面自行选择响应式且匹配主题的图片。

未找到、错误、禁止访问和维护页面各自拥有状态图。真实状态码、信息和操作仍是 HTML。首页也有独立构图的竖屏素材。

## 验证

- 素材测试核对每个配置文件及精确尺寸，并要求日夜来源不同。
- 组件测试核对响应式来源选择、主题切换和装饰性无障碍属性。
- 路由测试核对三个共享分组与嵌套页面继承。
- 浏览器审核在明暗主题、桌面/中等/手机宽度下透过真实不透明面板检查图片，确认没有水平溢出，也不会同时下载桌面与手机图。
