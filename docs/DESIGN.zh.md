# 门户设计约定

[文档首页](../README.md) · [English version](./DESIGN.md)

本文记录当前门户稳定的界面规则；精确数值仍以源码中的 CSS 与组件为准。

## 设计方向

门户采用克制的锻造材质界面，搭配电影感武侠环境。公会身份、全景场景、字体和少量领域色提供辨识度，控件保持熟悉、清晰且一致。避免为每个对象添加装饰边框、过度嵌套卡片、随意渐变，以及与内容争夺注意力的特效。

站点配置拥有公开站名和公会 Logo。公共页头、登录、邀请码注册、账号恢复、验证和状态页使用同一套身份。环境图不能替代成员头像、图库作品、物品照片或公告/百科的内容媒体。

## 字体与语言

- 正文使用 `Inter`；中文使用 `Noto Sans SC`，并以 `Microsoft YaHei` 和系统字体兜底。
- 展示标题使用 `Saira Semi Condensed`；代码和技术数值使用共享等宽字体。
- 英文和中文是同等完整的产品界面。较长译文不能被裁切、挤压标签或拆散相关控件。
- 标题负责建立层级；不能用边框或颜色代替清楚的标签和分组。

## 色彩、表面与图像

- 组件使用 `styles/semantic.css` 的语义 token 和 `styles/scale.css` 的尺寸 token，不得在单个页面内另写一套主题。
- 明暗主题都必须保持文字对比度、可见焦点、错误/警告含义和禁用状态的清晰度。
- 工作页使用 `components/layout/route-metadata.ts` 定义的三组路由场景；公共页、访问页和状态页使用各自的响应式素材。详见 [VISUAL_PRESETS.zh.md](./VISUAL_PRESETS.zh.md)。
- 可读内容放在不透明度足够的语义表面上。页面边缘可以看到场景，但不得降低可读性。
- 领域色用于公告、活动、公会战、仓储等实际含义；主操作色用于交互。二者都不能作为无含义装饰。

## 排版

- `PageLayout` 和路由元数据拥有阅读、标准、宽幅三种内容宽度；页面在可用工作区内居中。
- 每个区块只拥有一层间距边界，避免卡片套卡片、零散分隔线和间距互不相关的内容块。
- 桌面、平板和手机可以重新排列内容，但任务能力必须一致，且无需水平滚动就能操作。
- 表单将标签、输入框、帮助文字和错误信息作为一个整体对齐。宽度足够时密码要求可以放在字段旁边，小屏时应自然堆叠。
- 访问页和状态页卡片使用紧凑的可读宽度、均衡内边距和一个明确主操作，并显示配置的公会身份及已本地化的服务端或校验消息。

## 组件与交互

- 对话框、菜单、弹出层、选择、焦点和键盘行为使用由 Base UI 支撑的源码自有 shadcn/ui 组合组件。
- 服务端状态由 TanStack Query 管理；组件不能仅为样式重复一份请求状态。
- 每个任务区域只设置一个明显的主操作；次要和破坏性操作保留清楚标签及基于权限的状态。
- 加载、空内容、错误、禁止访问、未认证、未找到和维护状态必须解释发生了什么；存在有效后续动作时应提供入口。
- 加载使用顶部进度条和相关区域内的本地化转圈文字提示，不使用骨架色块。路由代码就绪后再替换当前页面；刷新时保留已有内容。列表筛选只可在同一会话和浏览模式下保留结果，新结果返回前暂停分页。减少动效会关闭转圈旋转和页面淡入。
- 动效只用于表达状态或空间变化。用户的“减少动效”设置和操作系统偏好必须移除非必要移动，同时保留结果。

## 无障碍与审核

每个改动页面都要检查英文和中文、明暗主题、键盘操作、减少动效，以及有代表性的桌面/手机宽度，并确认：

- 标题和标签语义正确；
- 焦点可见且 Tab 顺序合理；
- 文字、控件、错误和禁用状态对比度足够；
- 触控布局中的操作目标至少为 44px；
- 缩放及较长译文可以正常重排；
- 没有意外的水平溢出；
- 真实加载、空内容、校验、权限和服务端错误状态可用；
- 背景图保持装饰属性，不重复无障碍文字。

测试应保护行为、无障碍和响应式契约。精确像素、边框宽度和 CSS 类名属于视觉审核，除非它们承载真实产品不变量。
