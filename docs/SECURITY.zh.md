## 私下报告漏洞

疑似漏洞不要创建公开 issue。请使用仓库的 **Security → Advisories → Report a vulnerability** 流程，并提供：

- 受影响的路由、页面或配置；
- 影响及最短复现步骤；
- 凭据、私密公会数据或真实用户数据是否可能泄露；
- 建议修复方案（如有）。

请勿提供真实密码、会话 Cookie、有效邀请码、Cloudflare API token、私密公会数据或生产数据库导出。`wrangler.jsonc` 中的资源名称、D1/R2 标识和路由是配置标识而非认证秘密；该文件不受 Git 跟踪，但仍可对不希望分享的标识进行脱敏。

维护者会确认信息完整的报告、评估严重程度，并在公开披露前协调修复。仓库所有者在公开 fork 前必须启用 GitHub 私密漏洞报告。

## 产品安全边界

- 服务端权限校验是最终依据，客户端守卫只控制界面呈现。
- 会话使用 HTTP-only Cookie。修改请求要求通过 Origin 校验并带有 `X-Requested-With`；敏感路由组使用专门限流。
- 密码使用自描述 PBKDF2-SHA256 hash。`IG_PBKDF2_ITERATIONS` 默认及最低为 10,000，以适配 Cloudflare Worker CPU 限制；运行时实测后可显式提高到 10,000,000。登录只消耗一次固定配置的迭代预算。成本较低的 hash 会在成功登录后升级，高于运行预算的 hash 不会被认证；降低配置前必须先迁移已经存在的高成本 hash。
- 未知、不可用和密码错误账号返回同一通用凭据错误。按来源和来源/登录名组合的限流在账号查询与密码派生前执行；不存在持久账号冷却或管理员解锁路径。
- 角色和授权由 D1 拥有。用户管理严格向下，数据库原子保证至少一位活跃用户的当前角色拥有 `admin.roles.manage`。
- 富文本在服务端按严格节点/标记白名单校验。成员编写的行内 HTML 统一经过共享 sanitizer。响应包含 CSP、HSTS、禁止嵌入、`nosniff`、referrer 和 permissions policy。
- 持久图片使用经过验证的 WebP 变体，资料音频使用经过验证的 Ogg/Opus。共享媒体服务会比较声明 MIME 与 magic bytes、验证 Opus codec，并拒绝 SVG。
- 邀请使用随机 10 位大写字母数字码。由于其用于手动输入和重复分享，有邀请管理权限的管理员可以查看；验证与注册受限流，日志会脱敏邀请码。审计归档的列表、HEAD、Range 和下载请求始终使用普通登录会话及 `admin.audit.export` 授权。
- 审计归档和内容媒体共享一个逻辑 BlobStore，并使用不同 keyspace。Cloudflare 映射到 R2，VPS 映射到配置的文件系统目录。数据库清单而非对象列表是权威来源。

## 自托管责任

[SETUP.zh.md](./SETUP.zh.md) 是权威部署与更新指南。操作者只能选择 Cloudflare 或单进程 VPS 运行时，并负责保护运行时访问、使用 Wrangler secret 或受保护的 VPS 环境文件、应用经过审核的迁移、及时更新依赖，以及在获准的生产迁移前备份 SQLite/D1 和 Blob 存储。

媒体删除始终绑定精确的数据库生命周期变化。垃圾回收只选择已过期且无关联的资产，并删除记录中的精确 Blob key；任务不会扫描存储后猜测哪些对象未引用。管理 API 测试控制台受权限保护，其运行注册表按精确 ID 记录每个 fixture 和错误，并为可恢复目录修改保存 before-image。正常、停止或失败的测试会立即清理；有界定时恢复只处理因浏览器、网络或运行时故障而遗弃的运行。不要手动修补生产数据库，也不要直接改写或删除生产 Blob 对象；请使用经过审核的迁移、管理和维护流程。
